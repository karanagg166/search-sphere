## 1. Executive Summary

This milestone resolves critical edge-case failure modes across test fixture lifecycles, distributed lease contention during container restarts/rolling deployments, and raw container memory exhaustion under Render's 512 MiB cgroup limits.

All improvements adhere strictly to the $0 infrastructure budget constraint, leveraging existing Supabase PostgreSQL primitives and Linux cgroup v1/v2 telemetry without adding external paid services.

### Core Hardening Deliverables:

1. **Provably Safe CI Fixture Containment (`scripts/ci_production_smoke.py`)**:
   - **Account Ownership Verification**: Restricts fixture sweeps strictly to documents owned by the designated CI smoke test user (`user_id` match). User documents belonging to real users (`aggarwalkaran241@gmail.com`) can never be matched or deleted.
   - **Provenance Markers**: Every test document generated by the smoke test embeds an explicit provenance marker (`[CI_SMOKE:run_...]`) in both title and metadata.
   - **Persistent On-Disk Manifest (`.ci_smoke_manifest.json`)**: Tracks active and historical test artifacts across script interruptions, crashes, or unhandled exceptions.
   - **Multi-Page Pagination**: Upgraded listing logic to traverse `/documents?page=N&limit=50` across all pages instead of checking only the first page.
   - **Snapshot Iteration & Retries**: Iterates over snapshot sets (`list(set)`) to eliminate list mutation during iteration, and enforces individual HTTP response checks (200/204/404) followed by vector storage purge verification.

2. **Distributed Leases & Safe Rolling Restarts (`apps/api/src/services/durable_processor.py`)**:
   - **Worker Identity**: Each processor instance instantiates a unique worker ID (`w_{uuid4().hex[:8]}`).
   - **Structured Lease Protocol**: Formats lease tokens as `proc:{worker_id}:{expires_epoch}:{attempt}`.
   - **Elimination of Startup Lease Theft**: Replaced unconditional `force_all=True` startup recovery with safe, expired-only recovery (`force_all=False`). When a new API or worker container boots during a rolling deployment, it will not steal unexpired leases from living containers.
   - **Compare-and-Set (CAS) Concurrency**: Enforces atomic SQL updates (`WHERE id = :id AND status = :held_lease`) on claim, heartbeat, completion, failure, and recovery.
   - **Active Heartbeat Loop**: Background task extends lease expiration epochs every 20 seconds; aborts job execution immediately if CAS detects that another worker acquired or expired the lease.
   - **Terminal Dead-Lettering**: Jobs exceeding 3 retries transition directly to `failed:max_retries_exceeded`.

3. **Raw Container Memory Headroom Guardrails (`apps/api/src/services/memory_guard.py`)**:
   - **Container Headroom Isolation**: At ~497 MiB raw cgroup usage in a 512 MiB container, Linux page caches often report apparent reclaimability that does not materialize during sudden heap spikes. MemoryGuard now computes unallocated container headroom (`platform_limit_mb - raw_cgroup_mb`).
   - **Hard Workload Admission Thresholds**:
     - Heavy background tasks (indexing, extraction, batch embeddings) require BOTH safe working set headroom >= 30 MiB AND raw container headroom >= 25 MiB.
     - Interactive RAG queries require safe working set headroom >= 15 MiB AND raw container headroom >= 12 MiB.
     - Pressure escalates to `critical` if raw container headroom <= 16 MiB, `high` if <= 28 MiB, and `moderate` if <= 64 MiB.
   - Eliminates container SIGKILL OOMs during rapid allocations.
